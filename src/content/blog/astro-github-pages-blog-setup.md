日々の思考や技術的なメモ、開発の備忘録を書き残す場所として、この度**「並木秀作のブログ」**をゼロから自作・立ち上げました。

採用した技術スタックは、現代の静的サイトジェネレーター（SSG）の本命である **Astro** と、ホスティング環境としての **GitHub Pages** です。

実際に設計からデプロイまでを終えてみて感じたのは、**「表示速度が異次元に速い」「サーバー代が完全無料（0円）」「書く体験が最高に気持ちいい」**という三拍子揃った圧倒的な快適さでした。

本記事では、既存のブログプラットフォームではなくあえて「自作個人ブログ」を選んだ理由や、note風のデザインへのこだわり、静的サイトなのに実現した「予約投稿機能」の仕組みなどを詳しく紹介します。

---

## 1. なぜ既存プラットフォームではなく「自作ブログ」なのか？

note、Zenn、Qiita、はてなブログなど、現代には優れた投稿プラットフォームが無数に存在します。私自身もnoteなどを利用してきましたが、長く情報発信を続ける中で以下のような想いが強くなってきました：

1. **デザインとタイポグラフィをミリ単位でコントロールしたい**  
   文章を読んでもらう上で「余白」「行間」「フォントサイズ」の心地よさは極めて重要です。余計な広告やサイドバーのノイズを完全に排し、記事だけに集中できる静かな空間を作りたかったのです。
2. **独自ドメインで「自分の城（拠点）」を持ちたい**  
   プラットフォームの規約改訂やサービス終了に左右されず、自分のドメイン（`blog.vcmc.jp`）の下に永続的な資産として記事を積み上げたいと考えました。
3. **数字のプレッシャーがない、純粋な執筆空間**  
   フォロワー数、ランキング、おすすめアルゴリズムなどのソーシャル機能は刺激的である反面、疲弊の原因にもなります。純粋に「自分が書きたいものを書き、読みたい人が読む」場所にしたいという原点回帰です。
4. **ランニングコストをゼロに抑えたい**  
   WordPressなどをVPSで運用すると毎月1,000円〜数千円のサーバー代とメンテナンス負荷が発生します。「維持費0円で完全放置できる堅牢な構成」が理想でした。

これらをすべて満たす最高の選択肢が、**「Astro + GitHub Pages」** の組み合わせでした。

## 3. こだわった4つのポイント

### ① note風のシンプルで清潔感のあるタイポグラフィ

当ブログのデザインは、白を基調としたミニマルなトーン＆マナーに統一しています。

- **広めの行間と文字間**: 日本語が長時間読まれても目が疲れにくいよう、ゆったりとした `leading-relaxed` と `text-neutral-800` のソフトな文字色を採用。
- **コンテンツ幅の最適化**: 1行の文字数が多すぎると視線移動が疲れるため、最大幅を `max-w-3xl`（約768px）に制限。
- **見出しとリストのコントラスト**: 装飾過多にならず、かつメリハリがつくように左線のアクセントや淡い背景色を活用。

### ② バックエンド不要の「いいね（♡）」ボタン

noteで最も好きな機能の一つが記事末尾の「スキ」でした。読者からの温かいリアクションは執筆の大きなモチベーションになります。

商標等の観点から当ブログでは**「いいね」**と命名し、**サーバーやデータベースを一切持たない静的サイトのまま**、ブラウザの `LocalStorage` と CSS アニメーションを組み合わせて実装しました。

```astro
<!-- いいねボタンのコンポーネント例 -->
<button
  id="like-button"
  class="group flex items-center gap-2 px-5 py-2.5 rounded-full border border-neutral-200 hover:border-red-300 hover:bg-red-50/50 transition-all"
>
  <svg class="w-5 h-5 text-neutral-400 group-hover:text-red-500 transition-colors" ...></svg>
  <span id="like-count">0</span>
</button>
```

訪問者がハートを押すと、ふわっとしたアニメーションとともにカウントアップし、ページをリロードしても「いいね済み」の状態が保持されます。静的サイトでありながら、読者との小さな温かい接点を生み出しています。

### ③ 静的サイトなのに「予約投稿（時間指定公開）」を実現！

静的サイト（SSG）の最大の泣き所とされがちなのが、「明日の朝7時に公開したい」といった**予約投稿**ができない点です。

これを、**「記事の日付フィルタリング」×「GitHub Actions の Cron スケジュール」** を組み合わせることで、完全無料で解決しました。

#### 1. ビルド時に未来日付の記事を除外する
`pubDate` が現在時刻より未来の記事は、本番ビルド時に一覧や個別ルーティングから除外します（ローカル開発時はプレビュー可能）：

```typescript
// src/utils/posts.ts
export async function getPublishedBlogPosts() {
  const posts = await getCollection('blog');
  const now = new Date();

  return posts
    .filter((post) => {
      // 開発環境では予約記事も含めて全表示
      if (import.meta.env.DEV) return true;
      // 本番環境では指定日時を過ぎた記事のみ公開
      return new Date(post.data.pubDate) <= now;
    })
    .sort((a, b) => new Date(b.data.pubDate).getTime() - new Date(a.data.pubDate).getTime());
}
```

#### 2. GitHub Actions を毎時自動実行する
デプロイワークフローに `schedule` トリガーを設定し、毎時0分に自動で再ビルドを走らせます：

```yaml
name: Deploy to GitHub Pages

on:
  push:
    branches: [ main ]
  schedule:
    # 毎時0分 (UTC: 毎時0分 / JST: 毎時0分) に定期実行
    - cron: '0 * * * *'
  workflow_dispatch:
```

これにより、記事のフロントマターに `pubDate: 2026-10-24T07:00:00+09:00` と書いて push しておくだけで、**朝7時を過ぎた最初の定期ビルドで自動的に一般公開**されます。わざわざ指定時間にPCを開く必要はありません。

### ④ クライアントサイドの高速インクリメンタル検索

ヘッダーの検索アイコンやショートカットキー（`Ctrl + K` / `Cmd + K`）を押すと、即座に検索モーダルが立ち上がります。

ビルド時に全記事のインデックス（タイトル、概要、タグ、URL）を小さなJSONとして埋め込んでいるため、APIサーバーへのリクエスト待ちが一切なく、1文字入力するごとにリアルタイムで候補が絞り込まれます。

## 4. 圧倒的なパフォーマンスと表示速度

Astroの真骨頂は**「アイランドアーキテクチャ（Islands Architecture）」**です。

Next.jsやNuxtなどの一般的なフレームワークでは、静的生成した場合でもページ全体を動かすための巨大なJavaScriptバンドルがクライアントに配信・実行（Hydration）されます。

一方のAstroは、**「デフォルトではJavaScriptを一切ブラウザに送らない（Zero JS）」**という思想で作られています。必要なインタラクション（検索モーダルやいいねボタンなど）の最小限のコンポーネントだけをピンポイントで動かすため、ページのHTMLサイズは極限まで軽く、Lighthouseのスコアもほぼ全項目満点（100点）を叩き出します。

スマートフォンの4G回線や低速なWi-Fi環境下でも、リンクをタップした瞬間に画面が切り替わる感覚は病みつきになります。

## 5. 運用コストとランニング費用

気になる月々の運用コストですが、以下の通りです：

- **ホスティング費用**: **0円**（GitHub Pages）
- **CI / CD パイプライン費用**: **0円**（GitHub Actions のパブリックリポジトリ枠は無料・実質無制限）
- **SSL証明書（HTTPS）**: **0円**（Let's Encrypt 自動更新）
- **データベース費用**: **0円**（静的ファイル管理）
- **ドメイン費用**: 取得済みドメイン（`vcmc.jp`）のサブドメイン運用のため **追加費用0円**

**文字通り、完全無料（0円）で運用できています。** サーバーのセキュリティパッチ当てやOSアップデート、WordPressのプラグイン脆弱性に怯える日々とは無縁です。

## まとめ：自分のWebサイトを持つ楽しさ

お気に入りのテキストエディタで Markdown を書き、ターミナルで `git push` する。  
数十秒後には、自分で丹精込めて整えた美しいデザインのサイトに記事が世界中へ配信される。

この体験は、Web開発者・エンジニア・物書きにとってたまらなく心地よいものです。

プラットフォームのアルゴリズムに振り回されず、自分のペースで好きなことを好きなだけ表現できる場所として、このブログを大切に育てていきたいと思います。

Astro と GitHub Pages を使った個人ブログ構築、本当におすすめです！
